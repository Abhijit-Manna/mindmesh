As the Solution Architect for SolutionForge AI, I have designed the following high-level architecture to meet your HIPAA-compliant telemedicine requirements within the 4-month MVP timeframe, utilizing the requested open-source stack on AWS.

---

### 1. Major System Components
*   **Web/Mobile Frontend:** React SPA for patients, doctors, and admins.
*   **API Gateway:** AWS API Gateway for request routing, throttling, and security.
*   **Application Services (FastAPI):**
    *   *Auth Service:* User registration, RBAC, and JWT handling.
    *   *Consultation Service:* Booking, scheduling, and video session management.
    *   *EHR Service:* Patient profile and health record management.
    *   *IoT Data Service:* Ingestion and normalization of wearable device data.
*   **Database (PostgreSQL on AWS RDS):** Multi-AZ deployment for reliability and compliance.
*   **Video Infrastructure:** Amazon Chime SDK (leveraging AWS managed video services for HIPAA compliance and low latency).
*   **Audit Logging:** Dedicated service writing to immutable storage (S3 + AWS CloudTrail).

---

### 2. Communication & Data Flow
*   **Client to API:** HTTPS/TLS 1.2+ via API Gateway to FastAPI containers running on Amazon ECS (Fargate).
*   **Video Streams:** WebRTC via Amazon Chime SDK, ensuring peer-to-peer or relay-based low-latency streaming.
*   **IoT Data Flow:** Wearable devices transmit data to the IoT Data Service; data is validated and persisted in PostgreSQL.
*   **Data Residency:** All AWS resources will be pinned to the `us-east-1` (N. Virginia) or `us-west-2` (Oregon) regions to ensure US-only data residency.

---

### 3. External Integrations
*   **IoT Wearable APIs:** Integration modules for two primary device protocols (e.g., Apple HealthKit/Google Fit APIs).
*   **Identity Providers (Optional):** Integration with common OAuth2 providers (if needed for quick onboarding).
*   **Amazon Chime SDK:** For secure, HIPAA-eligible video conferencing capabilities.

---

### 4. Security Considerations (HIPAA Focus)
*   **Encryption:** AES-256 for data at rest (RDS/S3) and TLS 1.2/1.3 for data in transit.
*   **RBAC:** Role-based access control implemented at the middleware level in FastAPI, ensuring doctors only access assigned patient data.
*   **Audit Trail:** Every write operation and patient data retrieval request is logged with a timestamp, actor ID, and action type into an encrypted, WORM (Write Once, Read Many) S3 bucket.
*   **Isolation:** Use of VPC, private subnets for DB, and security groups to prevent public access to application logic.

---

### 5. Scalability & Reliability
*   **Scalability:** 
    *   **Compute:** FastAPI containers on ECS Fargate will autoscale based on CPU/Memory utilization to handle the 2,500 RPS peak.
    *   **Database:** Read replicas will be utilized to offload EHR data retrieval requests.
*   **Reliability:** 
    *   **Multi-AZ:** RDS and ECS deployments across multiple Availability Zones to ensure 99.9% availability.
    *   **Caching:** Redis (ElastiCache) for session management and frequently accessed patient metadata to reduce DB load.

---

### Detailed Analysis & Rationale

#### 1. Programming & Backend (FastAPI)
*   **Why:** FastAPI’s asynchronous capabilities allow the system to handle the 2,500 RPS peak with lower overhead than traditional frameworks. Its built-in Pydantic validation ensures that inbound IoT data and EHR entries strictly match the schema, preventing malformed medical data from corrupting the DB.
*   **Trade-off:** Python’s GIL can be a constraint; however, running on Fargate allows horizontal scaling to mitigate this easily.

#### 2. Database & Data Residency
*   **Why:** PostgreSQL is the gold standard for relational medical data. All instances will be restricted to `us-east-1` or `us-west-2` via AWS Service Control Policies (SCPs) to satisfy US data residency.
*   **Security:** Encryption at rest using AWS KMS (Customer Managed Keys) is required for HIPAA compliance.

#### 3. Authentication & Authorization (RBAC)
*   **Why:** Using **Amazon Cognito** or **Auth0** offloads the "Secure User Registration" requirement. They provide built-in Multi-Factor Authentication (MFA), which is a hard requirement for HIPAA.
*   **RBAC:** Role-based access control will be implemented at the API Gateway and application middleware level, ensuring only authorized doctors can fetch specific EHR records.

#### 4. Audit Logging (HIPAA Requirement)
*   **Why:** Every state-changing request (POST/PUT/DELETE) will be captured via middleware in FastAPI and pushed to an immutable **Amazon S3 bucket with Object Lock enabled** (WORM compliance). 
*   **Mapping:** Directly addresses FR07 (Audit trail logging).

#### 5. Scalability Strategy (2,500 RPS)
*   **Strategy:** ECS Fargate will use Target Tracking Scaling Policies based on CPU and RequestCount.
*   **API Gateway:** Acting as the front door, it handles DDoS protection (AWS Shield) and request throttling to ensure the backend is never overwhelmed, preventing service degradation.

#### 6. IoT Ingestion (FR04)
*   **Why:** Instead of direct writes to the DB, IoT data will hit an **SQS Queue**. The IoT service will poll the queue, perform normalization, and save to the DB. This prevents surges in wearable device traffic from affecting the performance of live video consultations.

---

### Implementation Risk Mitigation

*   **Timeline Risk (4 Months):** By using **Amazon Chime SDK** and **Cognito**, we save approximately 6–8 weeks of development time compared to building custom WebRTC signaling and auth systems.
*   **Security/Compliance:** Leveraging AWS services that are "HIPAA eligible" simplifies the BAA (Business Associate Agreement) process. Infrastructure must be deployed via **Terraform** to ensure that all security groups, encryption, and logging are consistent across environments.

### Final Recommendation for the MVP
1.  **Phase 1 (Month 1):** Deploy landing zones (VPC, RDS, Cognito) and build Auth/RBAC.
2.  **Phase 2 (Month 2):** Build EHR CRUD and Booking logic.
3.  **Phase 3 (Month 3):** Integrate Amazon Chime SDK for video and set up Audit Logging.
4.  **Phase 4 (Month 4):** Implement IoT Ingestion (SQS) and conduct Penetration Testing to confirm HIPAA readiness.

This stack minimizes technical debt while ensuring the platform is robust, secure, and compliant with all US healthcare regulations.
